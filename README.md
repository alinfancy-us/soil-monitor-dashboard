# SoilPulse Web Dashboard (soil-monitor-dashboard)

The official web dashboard for the SoilPulse soil temperature & moisture sensor. Fully static (`index.html` + `page/`) — no app install and no backend required: the browser connects directly to the device's GATT service (`0xFFE0`) over the **Web Bluetooth API** for live readings, history / daily-average charts, sensor calibration, temperature offset, device naming, firmware OTA updates, and factory reset.

Live: <https://soilpulse.alinfancy.com>

## 1. Features

| Module | Description |
| --- | --- |
| 📊 Data | Live temperature (°F/°C toggle), moisture and battery readings; last-5-record trend chart + 7-day daily average chart; measurement history table (cached in localStorage) |
| 📘 Guide | Quick start: battery installation, planting depth, Web Dashboard / Home Assistant setup, troubleshooting, FCC statement |
| ⚙️ Setting | Two-point moisture calibration (dry 0% / wet 100%), temperature offset (-10 ℃ to +10 ℃, 0.5 ℃ steps), device display name (≤ 20 bytes printable ASCII), firmware OTA update, factory reset & reboot |
| Global tools | Connect device, Refresh (triggers an immediate measurement), Clear data (clears the local cache + on-device history) |

Browser support: Web Bluetooth requires a **secure context (HTTPS or localhost)**. Use Chrome or Edge on Android / Windows / macOS. On iOS / iPadOS neither Safari nor Chrome supports Web Bluetooth — the page automatically shows a dialog guiding users to the **Bluefy** browser (with a deep link that opens this dashboard directly).

## 3. Local development

```bash
cd soil_monitor_dashboard
python3 -m http.server 8000
# Open http://localhost:8000 (localhost is a secure context, so Web Bluetooth works)
```

Or run `./start_service.sh`: serves on local port 8000 and opens a random public HTTPS tunnel via ngrok — handy for testing on a real phone.

Debugging tips:

- BLE traffic logs are gated by `DEBUG_ENABLED` in `page/js/config.js` (currently `true`); messages appear in the browser console with the `[SoilPulse]` prefix.
- The footer shows the frontend version (`PAGE_VERSION`) so you can confirm which build the browser actually loaded.

## 4. Versioning & cache busting

- `PAGE_VERSION` in `page/js/config.js` is the frontend version, shown in the page footer for cache troubleshooting.
- Scripts at the bottom of `index.html` are loaded with a `?v=x.y.z` query for cache busting. **Increment the `?v=` of any script you change**, otherwise browsers keep running the old JS.
- On production release, `deploy.yml` rewrites `PAGE_VERSION` from the git tag (with the `v` prefix stripped) — no manual sync needed.

## 5. Release pipeline

| Channel | Trigger | Target | firmware.json manifest |
| --- | --- | --- | --- |
| Production | push tag `v*` (deploy.yml) | Cloudflare Pages (custom domain `soilpulse.alinfancy.com`, see wrangler.toml) | With repo variables `FW_TAG` / `FW_NOTES` configured, downloads `SoilPulse_v<version>.bin` from the firmware repo Release and updates the manifest (isforce=false, regular version-check reminder only) |
| Test | manual workflow_dispatch (dev.yml) | GitHub Pages | The `fw_url` input points to the .bin (Actions Artifact / Release Asset / plain HTTP link), isforce=true forces the upgrade prompt |

Both pipelines assemble a clean `dist/` from `index.html + page/` before publishing; `page/firmware/` exists only inside the pipeline.

## 6. GATT protocol quick reference

Service `0xFFE0`; characteristic definitions live in `page/js/config.js` and must stay in sync with `app_att.h` in the firmware repo.

| Characteristic | Ops | Purpose |
| --- | --- | --- |
| `0xFFE1` | Read / Notify | Measurement data (timestamp / temperature / moisture / battery) and the last-5-record history packet |
| `0xFFE2` | Write | 4-byte Unix timestamp to sync the device clock |
| `0xFFE3` | Read | 7-day daily averages (`count` + 7 × daily record) |
| `0xFFE5` | Write | Clear on-device history (magic `CLR1`) / factory reset & reboot (magic `RST1`) |
| `0xFFE6` | Write | Two-point moisture calibration (`0` = dry, `1` = wet; the device first measures the current probe state, then applies calibration from that fresh sample) |
| `0xFFE7` | Write | Trigger an immediate measurement (Refresh button) |
| `0xFFE8` | Read / Write | Temperature offset (s8, 0.1 ℃ units, ±10 ℃ range) |
| `0xFFE9` | Read | Calibration status flags (bit0 dry / bit1 wet / bit2 non-zero temperature offset) |
| `0xFFEA` | Read / Write | Device display name (≤ 20 bytes printable ASCII, dashboard display only) |
| `0x180A` / `0x2A26` | Read | Standard Device Information Service, firmware revision (compared against the update manifest) |
| Telink OTA service | Write | Firmware transfer (dual-bank; the previous firmware keeps running if an update fails) |

> The advertised name is fixed to `SoilPulse` (used for `requestDevice` filtering). `0xFFEA` only changes the name shown on this dashboard — the phone's Bluetooth list keeps the built-in name, and nothing needs to be re-paired in Home Assistant.

## 7. Keeping in sync with the firmware repo

- Constants such as the GATT UUIDs, the advertised name prefix, calibration command values and the temperature offset range (±10 ℃) must match `bth_soil_sensor/app_att.h` and `app_config.h` in the firmware repo; always change both sides together, otherwise the dashboard cannot connect or writes invalid parameters.
- Firmware release flow: publish a Release in the firmware repo (asset named `SoilPulse_v<version>.bin`) → this repo's production pipeline fetches it via `FW_TAG` and attaches it to the `page/firmware/firmware.json` manifest → after connecting, the page compares versions automatically and prompts a one-tap OTA update.
